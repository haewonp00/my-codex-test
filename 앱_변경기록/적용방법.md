# Flutter + FastAPI 사진별·물건별 확인 기능 적용

## 이번 수정의 범위

첨부한 실제 `main.dart`, `pubspec.yaml`, `server.py`, `widget_test.dart`를 읽고 교체용 파일을 만들었습니다. Windows의 `C:\Users\haewo\...`에는 이 환경에서 접근할 수 없으므로 아래 파일을 Windows에 직접 복사해야 합니다. 원본 네 파일은 `앱_변경기록/원본/`에 보존했습니다.

이 ZIP은 **기존 프로젝트에 합칠 소스**입니다. Android/iOS 프로젝트 전체나 Flutter SDK가 포함되어 있지 않습니다. 기존 `android/`, 권한 설정, USB 연결 설정, Python 가상환경, `best.pt`는 유지하세요. 모델 재학습·임계값 조정·YOLO 클래스 추가·실시간 영상 기능은 없습니다. 모델 성능을 개선하는 변경이 아닙니다.

## 구현한 동작

1. 사진 촬영/선택 → 기존 `http://127.0.0.1:8000/predict`에 multipart `file` 업로드.
2. 서버가 기존과 같은 RGB/EXIF 보정 사진으로 YOLO를 실행. confidence=0.25, imgsz=640, CPU를 유지. IoU는 기존 라이브러리 기본값 0.7을 명시.
3. 기존 `count`, `image_width`, `image_height`, `detections`, `annotated_image`를 유지. 탐지별 `class_id`, `label`, `label_ko`, `confidence`, `bbox`도 유지. `detection_id`와 1부터 시작하는 `number`만 추가.
4. 같은 순서로 서버 이미지에 `#1`·`#2`, 앱 카드에 `#1`·`#2`를 표시. 번호는 사용자 수정·제외 후에도 바뀌지 않음. 서로 다른 분석은 새 ID를 사용.
5. 각 카드에서 AI 예상 종류·모델 신뢰도를 보면서 종류와 세부 품목을 직접 확인. AI 원본 값은 final로 보존하고 사용자 선택만 별도 변경.
6. 확인한 세부 품목 ID로 안내를 조회. 다른 카드와 상태는 그대로 남음. 안내 화면의 ‘품목 변경’도 해당 카드만 갱신.
7. ‘물건이 아니에요’는 카드를 삭제하지 않고 안내에서 제외. 복원하면 이전 확인 선택을 유지. 제외된 것은 확인 완료/안내 대상 개수에서 뺌. 탐지 개수는 원래 개수를 유지.
8. 새 사진을 실제로 선택하면 기존 상태 초기화. 선택 취소는 유지. 사진을 바꾸는 동안 도착한 이전 요청의 성공/오류는 모두 무시. 같은 사진의 중복 분석 시작도 차단.
9. 사진 없이 ‘직접 배출 방법 찾기’ 가능. 0개 탐지는 일반쓰레기로 판단하지 않고 다시 촬영·직접 찾기 제공.

**서버 번호 그리기를 선택한 이유:** 이미 Base64 박스 이미지를 보내는 구조이므로 같은 서버 이미지에 번호도 그리는 것이 단순합니다. EXIF 보정한 이미지와 YOLO의 xyxy 픽셀 좌표를 함께 사용하고 앱은 `BoxFit.contain`으로 완성된 이미지를 보여 줍니다. Flutter에서 사진 회전/여백을 추정해 박스를 다시 그리지 않습니다. Unicode 동그라미 대신 `#1`을 써서 Windows의 한글·특수문자 폰트 유무에 의존하지 않습니다. 제외한 박스는 원본 결과 보존을 위해 사진에 그대로 남고 카드에 제외 상태를 표시합니다.

## Windows 적용 순서

### 1. 기존 파일 백업하고 복사

앱/서버가 실행 중이면 중지합니다. 탐색기에서 기존 앱의 `lib`, `test`, `pubspec.yaml`과 서버의 `server.py`를 날짜가 붙은 별도 폴더에 복사해 백업하세요. 모델 `best.pt`도 기존 위치에 그대로 두세요.

ZIP 안의 **recycling_app 폴더 안** `lib`, `test`, `pubspec.yaml`을 `C:\Users\haewo\recycling_app`에 합쳐 복사합니다. `lib/main.dart`와 `test/widget_test.dart`는 교체되고 나머지 하위 파일은 새로 생깁니다. 기존 Android/iOS 폴더 전체를 삭제하거나 교체하지 마세요. 기존에 별도로 만든 다른 테스트가 있다면 유지하세요.

ZIP 안의 **recycling_server 폴더 안** `server.py`, `requirements.txt`, `requirements-dev.txt`, `tests`를 `C:\Users\haewo\recycling_server`에 복사합니다. ZIP에는 `best.pt`가 없으며 어떤 모델 파일도 덮어쓰지 않습니다.

### 2. 앱 패키지 설치와 정적 분석

VS Code 터미널(PowerShell)에서:

```powershell
cd C:\Users\haewo\recycling_app
flutter --version
flutter pub get
dart format lib test
flutter analyze
flutter test
```

추가 패키지는 공식 원문 열기용 **url_launcher ^6.3.2 하나**입니다. `flutter pub get`으로 설치합니다. image_picker와 http는 기존 것을 유지했습니다. SDK 조건 `^3.13.4`는 첨부 pubspec의 값 그대로입니다. 설치된 Dart가 이 조건을 만족하는지 `flutter --version`에서 확인하세요. 이 조건의 실제 충족 여부는 여기서 확인할 수 없습니다.

아래 서버 테스트는 별도이며 `flutter test`가 휴대폰 카메라나 실제 YOLO를 검증하는 것은 아닙니다. 기존 카운터 테스트는 앱 구조에 맞지 않아 교체했습니다.

### 3. 기존 서버용 Python 환경에서 설치·실행

기존에 서버를 실행하던 Python 가상환경이 있으면 먼저 VS Code에서 그 인터프리터를 선택하거나 활성화하세요. **다른 Python에 설치하지 않도록** 이후 명령은 모두 `python -m` 형태를 씁니다.

```powershell
cd C:\Users\haewo\recycling_server
python -m pip install -r requirements.txt
python -m uvicorn server:app --host 127.0.0.1 --port 8000
```

`C:\Users\haewo\recycling_server\best.pt`가 실제로 있어야 합니다. 코드 복사만으로 새 모델이 자동 적용되지 않습니다. 현재 사용하는 가중치를 그대로 사용하며, 실제 클래스가 plastic(0), paper(1), metal(2)인지 시작 시 검사합니다.

새 터미널에서 Galaxy S25를 USB로 연결하고:

```powershell
adb devices
adb reverse tcp:8000 tcp:8000
```

브라우저에서 `http://127.0.0.1:8000/health`가 열리고 classes가 맞는지 확인하세요. USB를 다시 연결했다면 adb reverse를 다시 실행해야 할 수 있습니다. 기존 인터넷/카메라 권한과 개발용 HTTP 설정은 이전 앱에서 작동하던 것을 유지합니다.

## 공식 안내를 나중에 넣는 곳

**`recycling_app/lib/data/guides.dart`의 `disposalGuides`**에 품목 ID를 키로 등록합니다. 키의 정확한 목록은 `items.dart`에 있습니다. 예를 들어 종이·신문은 `paper_general`, 음료용 종이팩은 `paper_carton`, 음료·식품 캔은 `metal_can`입니다.

등록할 필드:

- `actions`: 직접 확인한 공식 배출 행동 문구 목록
- `cautions`: 공식 주의사항 목록
- `institution`: 출처 기관
- `documentTitle`: 공식 자료 제목
- `verifiedReferenceDate`: 원문에서 확인한 작성일/기준일만 기입. 미확인이면 null
- `usageTerms`: 실제 확인한 공공누리 유형 등 이용 조건. 임의로 자유 이용이라고 적지 않음
- `officialImageUrl`: 실제 공식 안내 이미지의 직접 웹 주소. 없으면 null
- `sourceUrl`: 실제 공식 원문 링크. 없으면 null

현재는 **등록 데이터가 전혀 없고 배출 방법도 발명하지 않았습니다.** 행동·기관·제목·이용 조건이 비어 있는 미완성 자료도 화면에서 준비 중으로 취급합니다. 자료가 없으면 “이 품목의 안내는 준비 중입니다”, 이미지나 원문 URL이 없으면 해당 영역/버튼을 숨깁니다. 공식 이미지는 네트워크 URL 방식이며 존재하지 않는 assets를 등록하지 않았습니다. 나중에 로컬 이미지 파일을 쓰고 싶다면 assets 선언과 로컬 이미지 로딩을 별도로 추가해야 합니다. 이 구현에는 없는 이미지 경로를 미리 넣지 않습니다.

자료 추가 후에는 개발 중 hot restart 또는 앱 재실행으로 반영하세요. 사용자가 종류·품목을 바꾸면 새 ID로 안내를 다시 조회하며 이전 품목 안내를 유지하지 않습니다. 세부 품목/오염/재활용 가능 여부를 사진만으로 확정하지 않습니다.

## 검증 결과와 남은 확인

이 환경에서:

- 서버 pytest 8개 통과: 0/1/다중 탐지, 번호/ID, 픽셀 좌표·이미지 크기, EXIF 회전, 잘못된 파일/10MB 초과, 클래스 매핑 오류, 서버 오류, 모델 미존재.
- 실제 기존 label_fix_v1 가중치와 원본 사진으로 FastAPI 요청/응답 및 JPEG·번호·좌표 연결 검사. 결과는 `검증결과.json` 참조. 새로운 모델의 성능 평가가 아님.
- Dart 파일 전체 tree-sitter 구문 검사 통과. 이것은 Dart 타입 검사/Flutter analyze를 대체하지 않음.
- Flutter SDK가 없고 공식 SDK 다운로드가 네트워크에서 차단되어 `flutter analyze`, `flutter test`, Android 빌드/실제 Galaxy S25 실행은 수행하지 못함. Flutter 테스트 코드는 작성했으나 통과했다고 주장하지 않음.
- 모델 재학습·모델 파일 변경 없음.
