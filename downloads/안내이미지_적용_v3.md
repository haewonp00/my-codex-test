# 분리배출 안내 이미지 적용 v3

사용자가 업로드한 PNG 4장을 원본 바이트 그대로 앱에 넣었습니다. 인터넷 없이 안내 이미지를 표시하고 누르면 확대합니다. 사진 분석 자체는 이전처럼 PC 서버와 USB 연결이 필요합니다. 서버·best.pt·YOLO 클래스·추론 설정을 바꾸거나 재학습하지 않습니다.

## 품목 연결

| 사용자가 확인한 세부 품목 | 표시 이미지 |
|---|---|
| 종이·신문 | 종이류 수정.png |
| 상자·골판지 | 종이류 수정.png (공통 이미지 안의 상자 문구) |
| 음료용 종이팩 | 종이류 수정.png (공통 이미지 안의 종이팩 문구) |
| 투명 음료·생수 페트병 | 투명 플라스틱 수정.png |
| 기타 병·용기 | 플라스틱류 캔바.png |
| 기타 플라스틱 | 플라스틱류 캔바.png |
| 음료·식품 캔 | 금속류 수정.png |

모르겠어요, 스프레이·부탄가스 용기, 기타 금속, 비닐, 유리, 여러 재질 포장은 해당 안내 자료가 없어 준비 중을 유지합니다. 일반 금속캔 그림을 가스 용기의 전용 안내로 재사용하지 않았습니다. AI 클래스만으로 안내를 자동 확정하지 않습니다.

이미지의 출처·날짜·공공누리 제1유형 표기는 이미지에 적힌 내용으로 기록했습니다. 원문 URL은 제공되지 않았고 이 환경에서 확인하지 못해 링크를 만들지 않았습니다. 공식 검증 완료 또는 상업적 이용 권리 확인 완료로 표시하지 않았습니다. 날짜 2025/07/03도 확인된 원문 날짜 필드 대신 '이미지 내 표기'로 구분했습니다. 추가 배출 문구를 생성하거나 이미지 내용을 수정하지 않았습니다.

## 1. GitHub ZIP 다운로드

https://github.com/haewonp00/my-codex-test/blob/main/downloads/recycling_guide_images_v3.zip

파일 화면에서 Download raw file(↓) 또는 View raw로 다운로드한 뒤 모두 압축 풀기 합니다. 예시:

```text
C:\Users\haewo\Downloads\recycling_guide_images_v3
├─ Apply-GuideImages.ps1
├─ recycling_app
│  ├─ assets\guides\ (PNG 4장)
│  ├─ lib\data\guides.dart
│  ├─ lib\ui\guide_page.dart
│  ├─ pubspec.yaml
│  └─ test\ (안내 이미지에 맞춘 테스트)
└─ 처음읽기_이미지적용.md
```

## 2. Flutter 실행을 멈추고 패치 적용

실행 중인 flutter run 터미널에서 Ctrl+C로 앱 디버깅을 종료하세요. 서버는 변경하지 않으므로 서버 터미널은 그대로 두어도 됩니다.

```powershell
$patch = "C:\Users\haewo\Downloads\recycling_guide_images_v3"
Test-Path "$patch\Apply-GuideImages.ps1"
```

True라면:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$patch\Apply-GuideImages.ps1" -PatchRoot $patch -AppRoot "C:\Users\haewo\recycling_app"
```

원래 파일은 사용자 폴더의 recycling_guide_images_backup_날짜시간에 백업됩니다. pubspec.yaml, 안내 데이터/화면, 테스트와 이미지 4장만 복사합니다. 모델을 다시 받을 필요가 없습니다.

## 3. assets 반영·검사

```powershell
cd C:\Users\haewo\recycling_app
flutter pub get
dart format lib test
flutter analyze
flutter test
```

pubspec.yaml의 assets 선언이 추가되므로 pub get을 실행하고 앱을 완전히 다시 실행해야 합니다. hot reload만으로 끝내지 마세요. 새 패키지는 추가하지 않았습니다.

## 4. S25에서 다시 실행

기존 Python 서버는 실행 상태여야 사진 분석도 됩니다. USB가 다시 연결됐다면 reverse도 다시 설정하세요.

```powershell
adb reverse tcp:8000 tcp:8000
flutter run
```

adb가 PATH에 없으면:

```powershell
$adbPath = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
& $adbPath reverse tcp:8000 tcp:8000
flutter run
```

기기 선택이 나오면 S25를 고릅니다. 기기가 여러 대면 기존처럼 -s / -d 기기 ID를 지정합니다.

## 5. 가장 빠른 확인: 사진 없이 안내 열기

1. 첫 화면의 **직접 배출 방법 찾기**를 누릅니다.
2. **플라스틱 → 투명 음료·생수 페트병 → 이 품목으로 확인**.
3. 업로드한 투명 페트병 이미지가 나오는지 확인합니다.
4. 이미지를 누르고 손가락으로 확대/이동, 닫기를 확인합니다.
5. 품목 변경 → 금속 → 음료·식품 캔으로 바꾸면 캔 이미지가 나와야 합니다.
6. 품목 변경 → 기타 → 유리로 바꾸면 이전 이미지가 사라지고 준비 중이 나와야 합니다.

사진 분석 후 카드에서 확인한 품목으로 안내를 열어도 같은 이미지가 나옵니다. 다른 카드·확인 상태는 유지합니다.

## 파일 역할·추가 방법

- assets/guides/*.png: 제공 이미지 원본. ASCII 파일명으로만 복사해 Windows ZIP 한글 인코딩 문제를 피했습니다.
- lib/data/guides.dart: 품목 ID→이미지, 제공 이미지 내 출처·이용 조건 표기.
- lib/ui/guide_page.dart: 로컬 asset 우선 표시, 확대, 자료 없는 품목 전환.
- pubspec.yaml: assets/guides/를 Flutter 번들에 등록.
- test/: 실제 번들 PNG 로딩, 이미지 선택·확대·준비 중 전환 검증.

새 이미지가 생기면 assets/guides에 실제 파일을 추가하고 guides.dart에 해당 품목 ID의 assetImagePath와 실제 출처 정보를 등록합니다. 없는 품목의 이미지 경로를 미리 만들지 않습니다.

## 검증 상태

원본 PNG 4장의 디코딩·크기·SHA256 동일성, pubspec 경로, 7개 품목 매핑, Dart/PowerShell 구문, ZIP 내용을 검사했습니다. Windows에서 이전 버전의 analyze 0건·17개 테스트 통과를 사용자 로그로 확인했으나, **이미지 추가 후 Flutter analyze/test 및 S25 실행은 이 환경에서 수행하지 못했습니다.** 위 명령으로 이번 버전을 다시 확인해야 합니다.
