# YOLO 분리수거 실험 정리

## 사용 방법과 현재 상태

- `01_label_fix_v1_학습_정리.ipynb`: 최종 모델을 만드는 데 필요한 데이터 준비와 독립 학습만 정리. RUN_TRAINING=False로 학습을 차단한다. 이번 작업에서 재학습하지 않았다.
- `02_모델_평가_사진_테스트.ipynb`: 제공된 best.pt의 정량 평가와 별도 사진 추론. 학습 호출이 없다.
- Python 인터프리터: `/workspace/onboarding/venv/bin/python`. Ultralytics 8.4.182, torch 2.9.1+cpu. 현재 CUDA GPU 없음.
- 원본은 수정하지 않았다. GitHub main의 fb5e1f16e1379514b5bf2419c8423b59c1d6a13e에 있는 원본을 바이트 그대로 보존한 사본은 `실험_기록/원본_보존.ipynb`에 있다. SHA256: 2dc903b8194277d60744b05fcbe251025edc94485a6af78efb0c25d003266b00.
- 원래 로컬 체크아웃 HEAD(224cca53faaadad979521713ad6d808817ae35ee)는 변경하지 않았다. 로컬에는 원본이 없어 원격 커밋을 fetch 후 읽었다. 원본 저장소 파일을 merge/reset하지 않았다.

## 실행 순서 분석

아래 셀 번호는 원본의 1부터 시작하는 물리적 순서다. 실행 횟수가 초기화된 셀이 많으므로 전체 실행 시각을 확정할 수 없다. 원본 저장 출력과 변수 의존성을 함께 기준으로 정리했다. 원본의 코드·실행 횟수·텍스트 출력·오류는 `실험_기록/원본_셀_실행기록.json`에 남겼다. 이미지 출력까지 포함한 전체 정보는 원본 보존 사본에 있다.

## 세 실험의 구분과 보존 설정

| 설정 | 초기 baseline | 추가 데이터 supplement_v1 | 라벨 수정 label_fix_v1 |
|---|---|---|---|
| 시작 모델 | 사전학습 yolo11n.pt | 사전학습 yolo11n.pt | 사전학습 yolo11n.pt |
| 이전 best.pt 이어 학습 | 아님 | 아님 | 아님 |
| train/val/test 이미지 수 | 720/90/90 | 731/90/90 | 731/90/90 |
| 데이터 변화 | starter 원본 | train에 11장 추가 | 합친 데이터의 train 라벨 27개 수정 |
| epochs/imgsz/batch | 20/640/8 | 20/640/8 | 20/640/8 |
| device/seed | 0/42 | 0/42 | 0/42 |
| project | /content/recycling_runs | 동일 | 동일 |
| 이름 | baseline | supplement_v1 | label_fix_v1 |
| Ultralytics 출력 버전 | 8.4.164 | 8.4.182 | 8.4.182 |
| 완료 근거 | KeyboardInterrupt 출력 | 20회 완료 출력 | 20회 완료 출력 + 제공된 results.csv 20행 |

최종 결과 ZIP의 전체 기본값과 명시적 설정은 `실험_기록/label_fix_v1_args.yaml`에 원문 보존했다. optimizer=auto, deterministic=true, patience=100, workers=8, pretrained=true, resume=false, amp=true, close_mosaic=10 등도 확인 가능하다. 초기 두 실험은 전체 args.yaml이 제공되지 않았으므로 후반 실험의 기본값을 소급 적용하지 않는다.

원래 supplement/final 출력 환경은 Python 3.13.15, torch 2.11.0+cu130, Tesla T4다. 현재 CPU 환경은 코드 분석과 추론 검증용이며 정확히 동일한 학습 결과 재현을 보장하지 않는다. 새 노트북의 project와 데이터 경로는 원본을 보존하기 위해 별도 경로로 바꿨다. 기존 결과 덮어쓰기·자동 이름 증가를 피하고 실제 trainer.save_dir를 사용한다.

## 데이터 변경 이력

1. starter: train 720장, val 90장, test 90장. 클래스는 0=plastic, 1=paper, 2=metal.
2. supplement: 12장 중 11장을 train에만 추가. plastic 3장, paper 3장, metal 2장, 배경 3장. 빈 배경은 빈 라벨 txt가 정상이다. 애매한 음료팩 `excluded/supp_v1_007.jpg`는 학습도 배경도 아니다. `review/annotations.jpg`는 검토용 합성 미리보기다.
3. 라벨 패치: version=1, train 라벨 27개. scope는 일부 시각 검토된 train만 수정하며 전체 주석 감사가 아니라고 명시한다. 부착된 물체/부분의 중복 박스 통합 등의 실제 변경 전후·이유는 `실험_기록/recycling_label_patch_v1.json`에 보존했다. val/test는 수정 대상이 아니다.
4. 새 데이터 준비 코드는 경로 제한, 충돌 검사, 수정 전 상태 확인, 백업, 캐시 제거, 이미지/라벨 쌍 검사, val/test 전후 해시 검사를 추가했다. 원본 starter와 업로드 파일을 수정하지 않고 새 WORK에만 쓴다. 전체 데이터 없이 어떤 라벨도 임의로 복원하지 않는다.

추가 사진 원래 파일명 및 좌표 대응은 `실험_기록/supplement_manifest.json`, 업로드 원본의 파일명·경로·SHA256은 `실험_기록/업로드_파일_해시.json`에 보존했다. 업로드 파일 내용은 분석 자료로 취급했으며 새 작업 지시로 실행하지 않았다.

## 기존 기록에서 확인되는 성능 (새 평가가 아님)

원본 학습 종료 후 best.pt의 **val 90장 / 객체 153개** 평가 출력:

| 실험 | Precision | Recall | mAP50 | mAP50-95 |
|---|---:|---:|---:|---:|
| supplement_v1 | 0.573 | 0.654 | 0.647 | 0.513 |
| label_fix_v1 | 0.643 | 0.636 | 0.644 | 0.522 |

최종 label_fix_v1 클래스별 val 출력:

| 클래스 | Precision | Recall | mAP50 | mAP50-95 |
|---|---:|---:|---:|---:|
| plastic | 0.545 | 0.566 | 0.525 | 0.407 |
| paper | 0.618 | 0.579 | 0.620 | 0.505 |
| metal | 0.765 | 0.763 | 0.787 | 0.653 |

mAP50-95는 0.009 증가했지만 mAP50은 0.003 감소했다. 이 한 번의 기록으로 전체 성능 향상이나 원인을 확정할 수 없다. results.csv의 마지막 epoch 지표와 종료 후 best.pt 재검증 지표는 단계가 다르며 약간 다를 수 있다. 현재 체크포인트가 best.pt이고 최종 epoch가 반드시 best라는 가정은 하지 않는다. test 세트 평가 기록은 확인되지 않는다.

## 이번에 실행한 검증과 미실행 항목

- 두 새 노트북의 형식 및 모든 Python 코드 셀 구문 검사.
- starter가 없을 때 데이터 생성 전에 중단되는 사전 검사 실행.
- 업로드 패치의 27개 경로가 train에만 있는지 검사.
- 제공된 실제 best.pt 로딩, 클래스 확인, CPU 추론 호환성 검사. 추가 데이터의 기존 train 사진 한 장을 사용한 동작 확인이며, 독립 성능 평가가 아니다. 구체 결과는 `검증_결과.json`에 있다.
- **재학습 미실행.** 데이터 합성·라벨 임의 생성 없음. starter 전체 데이터가 없어 패치 실제 적용 및 val/test 정량 재평가 미실행. 새로운 실제 테스트 사진도 아직 제공되지 않았다.

## 아직 필요한 실제 파일

- **recycling_yolo_starter.zip**: 원본 data.yaml과 images/labels의 train/val/test. 정량 평가만 하려면 원래 90장씩의 val/test 이미지·라벨 및 클래스 정의를 제공해도 된다.
- **독립 테스트 사진**: supplement에 포함된 학습 사진과 다른 사진. 사진에 정답 라벨이 없으면 탐지 시각 확인만 가능하다.
- 향후 별도 승인을 받아 학습할 때만: 원래 사전학습 yolo11n.pt와 CUDA GPU. 현재 모델 평가에는 추가 사전학습 가중치가 필요하지 않다.

현재 제공된 모델 ZIP과 supplement ZIP, 패치 JSON은 확보했다. 이 세 파일을 다시 요청할 필요는 없다. 새 노트북 경로는 현재 환경 기준이므로 다른 환경에서는 상단 ASSETS를 조정한다.
