# 배경 오탐 실험 v1

## 실제 측정 결과

label_fix_v1의 기존 best.pt로 개발 평가 후보 16장을 측정했습니다. 정답 객체는 모두 0개입니다.

| 항목 | 측정값 |
|---|---:|
| 평가 사진 | 16장 |
| 오탐이 나온 사진 | 13장 |
| 사진 기준 오탐률 | 81.25% |
| 오탐 박스 | 13개 |
| 오탐 클래스 | 모두 paper |

설정은 confidence=0.25, IoU=0.7, imgsz=640, CPU, ultralytics=8.4.182입니다. EXIF 방향을 보정한 RGB 이미지를 Ultralytics 전처리에 전달했습니다. Confidence는 탐지가 맞을 확률로 해석하지 않습니다. 이번 사진에서는 높은 confidence의 배경 오탐도 확인됐습니다.

이 수치는 이번 16장의 결과입니다. 실제 사용 환경 전체의 오탐률로 일반화할 수 없습니다. 장소 독립성이 확인되지 않은 개발용 분리이며, 빈 배경만으로 객체 mAP나 recall을 계산하지 않았습니다. 모델은 재학습하지 않았으므로 개선 후 수치는 없습니다.

## 데이터 준비 내용

- 원래 label_fix_v1 데이터: train 731 / val 90 / test 90.
- 사용자 확인 배경 35장만 train에 추가: train 766장. 빈 배경은 기존 3장 포함 총 38장입니다.
- 클래스별 객체 수는 plastic 390 / paper 342 / metal 393으로 그대로입니다.
- 평가 후보 16장, 화질 보류 4장은 train 밖에 보관했습니다.
- 사용자 확인 배경에는 각각 0바이트 빈 라벨을 만들었습니다. background 클래스를 추가하지 않았습니다.
- 원래 이미지·라벨은 해시로 동일함을 검증했습니다. 기존 val/test와 best.pt는 보존했습니다.
- 앞서 검토한 두 장의 라벨 수정안은 이번 데이터셋에 섞지 않았습니다. 배경 추가만의 효과를 비교하기 위한 선택입니다.
- 실제 데이터 추가와 측정은 새 디렉터리에서 수행했습니다. 기존 데이터에 덮어쓰지 않았습니다.

## 파일과 실행

`background_experiment.py`: prepare(새 후보 데이터 준비), measure(기존 모델 오탐 측정). 재학습 명령은 없습니다.
`배경오탐_측정.ipynb`: 별도 데이터 ZIP을 푼 뒤 경로를 지정하고 측정하는 노트북. 학습 셀은 없습니다.
`recycling_fix.py`: 기존 검증·추론 함수의 동일한 복사본입니다. 이 보조 도구의 train-plan/execute 기능은 이번 실험에서 사용하지 않았습니다.
`측정결과/`: 사진별 CSV, 모든 탐지 박스·confidence가 담긴 JSON, 박스를 표시한 이미지 16장.
`confirmed_inventory.json`, `데이터_준비기록.json`: 원본 파일명·번호·해시·사용자 확인·분리 제안·원래 경로를 보존한 기록. 절대 경로는 이 환경의 이력입니다.

별도 `background_experiment_data_v1.zip`에는 준비된 후보 데이터와 개발 평가·보류 사진이 있습니다. best.pt는 포함하지 않았습니다. ZIP을 푼 위치를 노트북의 PREPARED에 지정하고 실제 best.pt의 위치를 WEIGHTS에 지정하세요. 노트북은 새 후보 data.yaml의 경로만 설치 위치에 맞게 바꿉니다. Python measure는 현재 PREPARED 아래의 평가 사진을 사용하므로 준비 이력의 과거 경로에 의존하지 않습니다.

원본 ZIP들에서 다시 prepare하려면 confirmed_inventory.json의 local_path를 실제 사진 위치에 맞춰 지정해야 합니다. source SHA256이 일치해야 하며, 기존 출력 폴더는 덮어쓰지 않습니다. 위 requirements.txt의 torch/torchvision 버전은 이번 CPU 측정 환경입니다. Colab GPU 학습 환경 설정을 의미하지 않습니다.

## 다음 실험 순서

1. 분리 제안에서 같은 장소가 train/개발 평가에 걸쳐 있지 않은지 촬영 기록으로 확인합니다. 지금 평가는 제안 버전의 기준 기록입니다.
2. 재학습을 별도로 승인한 뒤, 같은 초기 가중치·학습 설정·시드로 원래 데이터와 배경 35장 추가 데이터를 각각 학습합니다. 배경 추가 여부만 바꿉니다. 기존 final best.pt와 새 모델의 차이만으로 배경의 효과를 확정하지 않습니다.
3. 같은 개발 평가 사진에서 배경 오탐을 비교하고 기존 객체 val의 Precision·Recall·mAP 및 실제 재활용 물체 미탐도 확인합니다. 오탐을 줄이면서 진짜 물체를 놓치지 않는지 확인해야 합니다.
4. 별도 장소의 최종 테스트 사진을 확보해 포트폴리오에 최종 결과와 한계를 기록합니다. 16장은 개발 중 사용했으므로 최종 독립 테스트로 부르지 않습니다.

현재 데이터만으로 ‘다양성 부족이 유일한 원인’이라고 단정할 수 없습니다. 배경 오탐은 직접 측정했지만, 원인은 통제한 비교 실험으로 확인해야 합니다. 이번 결과를 보고 threshold를 임의로 올리거나 큰 paper 박스를 일괄 삭제하지 않았습니다.

## GitHub에 포함된 데이터셋

이 저장소에는 대용량 ZIP 대신 `데이터셋/` 안에 이미지·라벨 개별 파일을 저장했습니다. 저장소를 clone하거나 Download ZIP으로 받은 뒤 이 폴더를 그대로 사용하세요. 노트북 기본 PREPARED는 이 폴더를 가리킵니다. data.yaml의 path는 이식용 `.`이며, 노트북 첫 코드 셀이 실제 압축 해제/clone 위치로 바꿉니다. Ultralytics CLI에 직접 전달하기 전에 path를 실제 data 폴더의 절대 경로로 지정하세요. best.pt는 포함하지 않았습니다.

`데이터셋/data/`는 학습 후보 766장과 기존 val/test 각각 90장, `development_eval/`은 빈 배경 평가 후보 16장, `quality_hold/`는 보류 4장입니다. 파일의 실제 분리를 준비한 상태지만, 장소 독립성은 검증되지 않았으므로 분리 제안의 한계는 그대로입니다. 모델을 재학습하거나 기존 원본을 덮어쓰지 않았습니다.

원래 데이터 출처는 `수정안_v2/README.md`에 보존했습니다. 사용자 촬영 배경은 업로드된 55장입니다. 기존 데이터의 전체 출처 문서는 데이터셋 내부 README를 확인하세요.
